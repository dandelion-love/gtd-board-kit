# Push technology in 2026

* [Android notification channels and limits](android-notification-channels-and-dnd.md) - On Android every notification belongs to a channel whose importance the user controls; Do Not Disturb bypass and full-screen intents exist but are user-gated, and since Android 14 full-screen intents are reserved for calls and alarms
* [APNs and FCM native push](apns-and-fcm-native-push.md) - Native apps receive push only through Apple's APNs and Google's FCM; both are free to send, but each needs a vendor account, a signed app and server credentials, which is heavy for a small open-source kit
* [Declarative Web Push](declarative-web-push.md) - A Web Push payload in a fixed JSON shape that the browser shows itself, with no service worker code; shipped in Safari on iOS/iPadOS 18.4 and macOS Safari 18.5, still not in Chrome or Firefox in November 2026
* [Desktop notification delivery](desktop-notification-delivery.md) - On Windows, macOS and Linux the cheapest path is browser Web Push, which needs the browser or installed web app running; native OS notification APIs need an app, and Flutter's FCM plugin has no Windows or Linux support
* [Web Push on iOS Home Screen web apps](ios-home-screen-web-push.md) - Since iOS 16.4 a web app added to the Home Screen can receive standard Web Push through APNs with no Apple developer account, but only after install and a user tap, and with fewer options than native apps
* [iOS interruption levels and Focus](ios-interruption-levels-and-focus.md) - iOS ranks notifications as passive, active, time-sensitive or critical; only native apps can set a level, time-sensitive needs a capability and critical needs Apple's approval, so a web app is always "active" under Focus
* [Persistent connections on mobile](mobile-persistent-connections.md) - Holding a WebSocket, SSE or long-poll open from a phone works on Android only inside a typed foreground service with a visible notification, and does not work on iOS at all once the app is suspended
* [Notification action buttons](notification-actions.md) - Action buttons work in Web Push on Chrome, Edge and recent Firefox but not Safari or iOS web apps, inline text reply is native-only, so a board ask from a notification must degrade to "open the item" and anything that approves must require unlock
* [Push technology choice for 2026](push-tech-choice-2026.md) - Standard Web Push, sent in the Declarative Web Push format, is still the cheapest single technology that reaches Android, iOS and desktop in 2026, at the cost of an iOS install step and no Focus break-through on iPhone
* [Web Push standard](web-push-standard.md) - Web Push is three IETF RFCs (protocol, encryption, VAPID) plus the W3C Push API; any server with a key pair can send an encrypted message to a browser's push service without an account
