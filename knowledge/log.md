# Update log

## 2026-11-03

* **Added**: evidence on the issue and review requests (kit 0.21.0). The new model concept `evidence-places` says where each kind of evidence goes: the PR's evidence table stays the gate, and GitHub issue artifacts keep the approved plan, outside links and reports on the issue; a sub-issue is never evidence. The server spec gains the optional Issue artifacts group (`issue_artifact_list`, `_get`, `_create`, `_update`; no delete) and conformance A1 to A4. A new base label `agent-review` is a person's request for an agent to review an issue: `issue_labels` and `capture` refuse it from an agent (P4), a dispatching server starts a review run from it, and the new skill `board-review` does the review and posts one comment of findings. `board-report` 0.4.0 and `board-decompose` 0.2.1 point at the evidence rule. Profiles must add `agent-review` when they repin.
* **Added**: epic shape and board fields (kit 0.20.0). `board-decompose` 0.2.0 writes the epic body with every section the decomposition research calls for (Problem, Outcome check, Scope, Out of scope, Stories, Decisions, Risks and open questions, Gates) and fills each new item's board fields. The bodies live in `skills/board-decompose/templates.md`, and `templates/issues/` ships them as GitHub issue templates. The new model concept `board-fields` says who writes each standard field (Epic, Size, Priority, Lane, Owns, Gates, Agent, Last report, Start date, Target date) and when, and how a card waiting on a person's gate says which gate and what is asked; profiles should give the owner's `needs:*` label its own column instead of `Blocked`. `board-report` 0.3.1 points at it.
* **Added**: view filters (kit 0.19.0). A profile must not declare a view whose filter uses a deprecated qualifier; the first is `last-updated:`, replaced by `updated:` with a date (`is:closed updated:>=@today-7d`). GitHub warns on it and will drop it. A live view that still has one is reported for a person with the filter to type, because the API cannot edit a view, even when the repo kept the view. Conformance gains P9, and `board-onboard` 0.5.0 checks the repo's live views.
* **Fixed**: the Codex SessionStart hook initialises `.gtd/kit` before it runs `agent_guard.py` (kit 0.18.2), as the Claude hook does. Before, a Codex-only session in a fresh checkout never ran the guard and the linked skills stayed unresolved.

## 2026-11-02

* **Changed**: B3 waits out board lag (kit 0.18.1). GitHub Projects can serve the old item order for a while after `project_item_move`, so the runner re-reads `project_items` for up to 30 seconds before failing B3, as P6 and C8 do for label-filtered lists. What a server must do is unchanged.
* **Added**: agent guidance (kit 0.18.0). `board-claim` 0.4.0 hands back through the server's `pr_open`, with its own GitHub tool only as a fallback when the server lacks it. The new skill `board-decompose` splits an epic into stories or a story into steps the standard way and proposes them for a person to promote. `tools/pr_check.py` is a report-only PR check (evidence per criterion, test changes, claim records) with a daily `--audit` of agent actions, and `templates/workflows/gtd-pr-check.yml` is the template a person installs. `tools/agent_guard.py` is one Claude Code and Codex hook: it denies an agent's own PR create while `pr_open` exists (`GTD_GUARD_PR_OPEN`) and workflow edits without a merged grant for that repo, and prints a SessionStart reminder. The installers add the Codex hooks and link skills into `.agents/skills`, and skip what an older pin lacks. The spec: `item_claim` returns the ready verdict as a warning and never refuses on it (R8), and `sub_issue_add` and `issue_type_set` enforce the Kind parent rules (K1 to K4, 39 golden cases in `conformance/kind_cases.json`, `--kind-cmd`). R5 accepts GitHub's own refusal of a blocker cycle when `issue_blocked_by_add` passes the reason through.
* **Added**: the ready check (kit 0.17.0). `server-spec/ready-check.md` specifies `item_ready`, a read-only tool in the new Readiness group: it returns `ready`, `ready-blocked` or `needs-refinement` with the failed rules (acceptance criteria present, no open `needs:*` question, every blocker a native link, no blocker cycle, Size within `pickup_sizes`) and the open blockers, and writes nothing. Conformance gains R1 to R7, with 25 golden cases in `conformance/ready_cases.json` that the runner checks against its reference or a server's own logic (`--ready-cmd`). `board-pickup` asks it when the server offers it.
* **Changed**: the Kind list (kit 0.16.0). `server-spec/repo-context-and-profiles.md` gains Kinds: the standard Kinds (epic, story, chore, bug, spike, research, finding), steps as checklist items rather than a Kind, the retired Kinds `task`, `question` and `decision` with what replaces each, Issue Types as carriers with `kind:*` labels only as a fallback, and how a repo moves off the retired Kinds when it repins. Conformance gains P8: no profile declares a retired Kind. `board-needs-person` says a question is never its own issue.
* **Added**: agents open PRs through the server (kit 0.15.0). The optional Pull requests group defines `pr_open` (work): the server opens the PR with its own App credential, so the owner can approve it, and ends the body with a `gtd-pr` provenance marker naming the caller's principal. The caller must hold a claim on every issue the PR works on, and `Closes #n` is written only for verified work (`closes`) into the default branch. Conformance gains PR1 to PR3 (`--pr-head` for the one that opens a PR).
* **Added**: claims for stories combined on one branch (kit 0.14.0). An agent claims every story it works on, one claim and lease each, even on an integration branch the owning session runs; no record or tool claims several items. `item_claim` takes an optional `branch`, stored as `mandate.branch`; `board-claim` says how to claim, renew, release and open the PR for a batch; BOARD.md rule 5 says so; conformance gains C14.
* **Added**: how work decomposes (kit 0.13.2). The decision `decomposition-standard` settles the research's nine open questions: epic, story, step; `task` becomes story-level `chore` or a step; `finding` stays and `question` and `decision` retire as Kinds; an epic is done when its children are closed and its outcome check passed; ready is a read-only server check (spec to follow); an agent works one or more stories and claims each; agents open PRs through the server; small epics skip intent approval and work on a working system skips the skeleton; `kind:*` labels only where a repo has no Issue Types.
* **Added**: research on decomposing work into epics, stories and tasks (kit 0.13.1). `knowledge/decomposition/` holds 79 draft concepts in seven sections (agile foundations, agentic methods, skill landscape, GitHub primitives, work item kinds, acceptance and verification, human gates) and an overview with the decisions left to the owner. Research only: no skill or spec changes.
* **Added**: declared tool classes (kit 0.13.0). A server may class a tool of its own, one the spec does not name, by declaring `"gtd-board-kit/class"` in the tool's `_meta` in `tools/list`; the fence treats it like a spec class, an undeclared tool stays `full`, and a declaration on a spec tool must agree with the spec. X2 checks declared classes. P6 and C8 re-read a lagging label-filtered list for up to 30 seconds before failing.

## 2026-11-01

* **Added**: one connector per account (kit 0.12.0). Agent sign-in says an account keeps one gtd MCP connector, signed in as one shared agent, because a host loads every connector into every session; an agent that needs its own name uses the device-code entrance, and no agent adds or asks for a second connector.
* **Changed**: a conformance run earns the claim (kit 0.12.0). A server starts with no level and claims one only after the kit's runner, at the version it names as `spec_version`, made that level claimable and a person confirmed its manual checks. The runner reports the claimable levels and the manual checks left (also in `--json`), and `conformance/README.md` gives agents the procedure to certify a server.
* **Added**: work items live on the board (kit 0.11.1). The decision `work-items-live-on-the-board`: the issue is the record for epics, stories, tasks and bugs; a local markdown copy is a gitignored cache, a file sync reads only tracked files, and a backlog moves from files by untracking first, then copying bodies into issues.
* **Added**: the server declares its spec version and honest levels (kit 0.11.0). `server-spec/transport-and-identity.md` adds `/.well-known/gtd-board-kit` (`spec_version`, `conformance`, `mcp`, `join_url`, no auth) that agrees with `whoami`, and a server lists a level only when its checks pass. The new model page `server-version` says how an agent reacts: run a skill only when its level is claimed, and tell the person once when the server's spec version and the kit pin differ. Conformance gains T8 and T9; BOARD.md rule 1, `board-pickup` and `board-onboard` point at it.
* **Changed**: per-repo customization clarified (kit 0.10.1): fingerprints leave out the advisory `manual` key; a reconciler compares live items by a defined comparable shape per kind (label names case-insensitive), infers only from a complete read, combines overrides of repos sharing a board (a departure wins, disagreement reported), and an override without `seen` stays a notice.
* **Added**: per-repo customization (kit 0.10.0). `server-spec/` defines `overrides` (`skip` and `keep`) in `gtd-context.json`, a ledger of what a reconciler created from which declaration, item fingerprints in `profile_get`, and the upstream change notice that `profile_updates` returns when the profile changes an item a repo skipped or reshaped. Conformance gains O1 to O3; `board-onboard` surfaces the notices.
* **Added**: the spec and its checks change together (kit 0.9.0). `tests/check_kit.py` checks that every check id in `server-spec/conformance.md` is in the runner and back, and that the fold table matches its fixtures; `tools/spec_pair.py`, run by the `pre-push` hook, fails a branch that changes `server-spec/` without its checks unless a commit carries `Conformance-unchanged: <reason>`; a PR template asks for both.
* **Added**: the conformance runner drives the connector entrance (J11, JC1 to JC9) as an OAuth client with a loopback redirect; a person approves once in a browser (kit 0.8.0).
* **Changed**: one join, two entrances (kit 0.7.0). Agent sign-in starts with which entrance to use: the connector when the host keeps the sign-in, the device code when it keeps a file, and neither in an ephemeral container. It covers reconnecting the connector, a network policy that blocks the server, and whose name connector work goes under. `server-spec/agent-join.md` defines the connector entrance as a contract, `whoami` gains `entrance`, and conformance gains J11 and JC1 to JC9.
* **Added**: `conformance/`, a standard-library Python runner that checks any server against the spec's numbered checks over HTTP, with the claim-fold golden cases as JSON; the spec gains check T0 and fold cases i and j (kit 0.6.0).
* **Added**: `server-spec/`, an implementation-neutral specification of a compatible gtd MCP server, with conformance checks and a unit-by-unit work plan (kit 0.5.0). Onboarding now reads views with `project_views_list`, the read-only tool.
* **Added**: agent sign-in, the agent-side contract for joining the gtd MCP server, with flow diagrams.
* **Added**: the kit-as-interface decision and the queue and ETA pattern: native GitHub constructs carry the state, and a person's edit wins.
* **Added**: standing lanes and workflow grants (kit 0.4.0), and a reference on DeepSeek's dsh-superagent, which the lane design borrows from.

* **Added**: the kit's knowledge as an OKF 0.2 bundle, with the board model, the kit's design decisions, and the pinned OKF specification.
