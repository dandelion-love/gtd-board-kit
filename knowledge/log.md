## 2026-11-05

* **Added**: signed pull request writes (kit 0.32.0). A comment, a review and a reply on a review thread now carry a sign-off like any issue comment. `issue_comment` on a PR number must work and is written under the server's App identity; the Pull requests group gains `pr_review` (`event` `comment` or `request-changes`, never `approve`, and `request-changes` refused on the server's own PRs, which GitHub would reject; the body and each inline comment signed, `act` `pr-review`; validated whole before anything posts) and `pr_review_reply` (`act` `pr-reply`; optional `resolve`, reported apart from the reply, and a resolve-only retry posts nothing). `sign-offs.md` gains Pull request writes: never under a person's account and no fallback to one, the caller's authorization checked before any App call, and a role default taken from claims on the issues a trusted `gtd-pr` marker names, never from a forged one. Conformance gains PR5 to PR7 and PR8, PR9 (by hand). `board-claim` 0.8.0 answers review findings with `pr_review_reply`, `board-review` 0.6.0 may leave line findings with `pr_review`, and `who-said-what` lists the new acts.
* **Added**: the server pings for an ask (kit 0.31.0). The new optional Notifications group (`server-spec/notifications.md`) fixes the contract: the repo maps each `needs` value to a login in `.github/gtd-context.json` under `notify` (with `push` and `new_issues`); `notify_get` (read) returns the map, the identity the server pings as (`ping_as`, never the person pinged) and an item's trusted pings; `item_report` with `attention` posts one separate, signed ping comment (`act` `ping`, a `gtd-ping` marker keyed on the item, `needs` and a hash of the question), so a repeat posts nothing and a changed question pings again, and returns `ping` (`posted`, `unchanged`, `no-map`, `no-identity`, `failed`); a non-draft `pr_open` requests the owner's review; an optional Web Push copy of each ping and each review request uses the key as `tag` and `Topic`, with `reason` `ask`, `pr-ready` or `stop`. Conformance gains N1 to N5 (N2 reads the ping's author from GitHub with `--github-token-env`) and N6 to N8 (by hand). BOARD.md rule 7 and `board-needs-person` 0.4.0: on such a server agents write no mention and check `ping`.
* **Changed**: never notify a person as that person (kit 0.30.1). GitHub skips your own actions, so a mention or review request written under the mentioned person's account reaches nobody. The decision `notify-only-when-a-person-must-act` gains point 3: anything meant to notify a person goes out under another identity, by default a GitHub App installation (`[bot]`); with none, the ask is posted unpinged and the result says so. The GitHub gaps page, the BOARD.local.md template and `board-needs-person` 0.3.1 say the same.
* **Added**: notifications research and a decision (kit 0.30.0). The new folder `notifications/` holds 33 draft concepts: what GitHub notifies and never notifies (Projects send nothing, your own actions never reach you), when DeepSeek's dsh-superagent lets an agent speak, design prior art (PagerDuty, Novu, Knock, Courier, Slack, Linear, coding agents, interruption and alert-fatigue research), 2026 push technology (Web Push, Declarative Web Push, iOS and Android limits, desktop, action buttons) and push services (ntfy, Gotify, UnifiedPush, Pushover, Apprise, Sygnal, autopush). Decision (draft): [notify a person only when they must act](decisions/notify-only-when-a-person-must-act.md). BOARD.md rule 7 says only an ask pings, with one @mention of whom `.gtd/BOARD.local.md` maps to `needs`; the template gains a Notifications section, onboarding asks for it, and `board-needs-person` 0.3.0 starts the ask with that mention.
* **Added**: an intake for requests between projects (kit 0.29.0). A project's intake is its repo plus a label (`agent-proposed` by default). The new optional Intake group has `intake_list` (read: open requests, each with its latest ack, `overdue` past `ack_within`, `new` since a cursor, `comments_since` and the `reply_on` issues it names) and `intake_ack` (work: a signed `gtd-ack` record, `received`, `taken`, `parked` or `handed-back`; a repeat posts nothing). `board-lane` 0.5.0 adds `intake.md`: the receiving end runs an observe-first intake lane that speaks to the owner only for a new request, and the filing end flags `needs:<owner>` on its own item when its request goes unacknowledged, so a dead path between projects reaches a person. The template gains an Intake section with a "Files to" list. Conformance gains I1 to I4 and I5 (by hand). Decision: [requests go through an intake](decisions/intake-and-acks.md).
* **Changed**: lane items stay small (kit 0.29.1). A tick renews the lane item only when under two cadences of its lease remain, and the template's lease is now `26h`, so an hourly lane writes about one renew a day instead of 24. A lane item rolls over to a successor at 300 comments (`board-lane` `resources-and-long-jobs.md`, Lane item size). The cost: a dead lane shows up to a day later.

## 2026-11-04

* **Added**: sign-offs, so a person can tell who said what (kit 0.28.0). Everything the server writes for a caller (an `issue_comment`, each claim record, a `pr_open` body) now ends with a visible `gtd-sign` line and one `<!-- gtd-sign v1 {...} -->` marker naming the verified principal (`by`), its `role` (`worker`, `reviewer`, `coordinator`, or `owner` for a person only), the `act` (`comment`, `review`, `claim`, `renew`, `release`, `report`, `pr`), the caller's `session` and the time. `issue_comment` gains `session`, `role`, and `review_stage` with `review_verdict`: a review verdict needs the caller's live review claim, so no session signs a verdict on its own work, and the server writes the `Work review: Needs changes` line itself. A body holding a sign-off marker refuses, and readers trust one only under the server's own author. The new spec page `server-spec/sign-offs.md` fixes the format, conformance gains G1 to G5 (Core) and PR4, the model concept `who-said-what` gives the GitHub search recipes, and `board-review` 0.5.0 passes the verdict as arguments. Earlier comments are never edited to add a sign-off; `who-said-what` says how to post a backfill note per item instead, with the person's authorization, one row per earlier contribution and a named `basis` (`record`, `pr-marker`, `self-tag`, `footer`, `linked`, `log`, `unknown`).
* **Added**: agents see what others wrote (kit 0.27.0). The Core read `activity_since(repo, since?)` lists comments, reviews and inline review comments created after `since` on issues the caller holds, PRs whose `gtd-pr` marker names it, and the repo's channel issues, never records. Each result carries `read_at`, the cursor the caller passes back; with none it covers the last 24 hours. A renew no longer hides `follow_ups` (C9 changed). `board-report` 0.8.0 adds New activity; `board-lane` 0.4.0 reads it each tick; `board-claim` 0.7.0 points review answers at it. New checks C16, C17 and C18 (by hand). Decision: [agents pull new activity](decisions/agents-pull-new-activity.md).
* **Added**: typed links between items (kit 0.26.0). The new model concept `typed-links` and `server-spec/typed-links.md` fix a link record (`link` with `from`, or `id`, `to`, `kind`, `why`; `unlink` takes one back), eleven kinds with the name each far end reads (`depends-on`/`blocks`, `follows-up`, `references`, `evaluates`, `rests-on`/`supports`, `refines`, `contradicts`, `corroborates`, `supersedes`, `reuses-material`, `shares-listener`), and the fold that turns a repo's register lines into edges. Only `depends-on` becomes a native blocked-by; parent stays the item's own sub-issue link and is never a link kind; every other kind is a Related line in the mirrored body on both ends. A repo may render the same fold as an OKF graph (an index with a Mermaid diagram, a page per item) with a check mode. Conformance gains L1 (22 golden cases in `conformance/link_cases.json`, `--link-cmd`) and L2 (manual), and the work plan gains U14.
* **Added**: ticked criteria and a named review stage (kit 0.26.0). At its `ready` report the worker now ticks each acceptance criterion whose evidence row passes and adds its pointer (`Evidence: PR #n, AC2 row`); a failing or missing row leaves the box empty, and the person's merge confirms the ticks (`evidence-places`, `board-report` 0.7.0). A review's verdict line now names its stage, `Plan review` (no PR yet) or `Work review` (a PR exists), so a verdict on finished work is never read as a readiness check; a work review checks every tick, pointer and the PR's `link` artifact (`board-review` 0.4.0). `evidence-places` also says what GitHub allows in an artifact name (no `#` or `:`). A new model concept, `self-reviewable-items`, says each item must speak for itself: a person judges it from the issue alone, in about a minute, through its Status, labels, ticked criteria that link straight to their proof (a permalink, a run, a page), the PR as a `link` artifact and one short `ready` report naming the one action asked. A summary table elsewhere never replaces that; a work review checks it.
* **Added**: lanes that outlive their session and keep their hand-offs (kit 0.25.0). A new base label `standing` marks an item that stays open by design (a lane's item, a standing chore): `item_ready` refuses it (R7), so it no longer reads as unready. The SessionStart hook now prints `lanes.py resume`, so any new session sees the lanes to re-schedule after the old one's schedule died. A `waiting` report on work only a lane can do also comments on the lane's item, and `board-lane` 0.3.0 reads those `follow_ups` as hand-offs each tick (`board-report` 0.6.0). `lanes.py` skips `example-*` blocks, so the shipped template lints clean.
* **Fixed**: a pull request no longer closes items by accident (kit 0.24.0). GitHub closes an issue on merge when the PR body or a commit message holds a closing keyword (`close`, `fixes`, `resolved`, ...) before an issue reference, anywhere in the text, so a rollback note such as "hold or close #<n>" closed a lane's item when its PR merged. `pr_open` now refuses a body, or a commit message between base and head, that holds one (only the server writes the closing line, when `closes` allows it); conformance PR2 checks the body. `board-claim` 0.6.1 says so and drops `Closes #n` from the fallback path. A branch name never closes an issue.
* **Added**: agent-requested reviews, never by the same session (kit 0.23.0). An agent may now add `agent-review` to ask another session to review its finished work (`issue_labels` and `capture` allow it; P4 changed). `item_claim` gains `purpose` (`work` or `review`) and `session`, an opaque name the caller gives its session; both are recorded in the claim's `mandate`. A review claim needs a `session`, is never `inferred`, and refuses when its `session` matches the session of any earlier work claim on the item, so no session reviews work it did; a fresh session of the same agent may. Conformance gains C15. BOARD.md rule 5 asks for the `session` on every claim, `board-claim` 0.6.0 passes it and may add `agent-review` on hand back, and `board-review` 0.3.0 claims with `purpose="review"`.
* **Added**: merge grants and work with no issue (kit 0.22.0). Rule 9 now opens two ways, both only through a grant merged into `.gtd/BOARD.local.md`: a workflow grant (unchanged) and a new merge grant. A merge grant names exact files, never a folder, a pattern or anything under `.github/` or `.gtd/`; an agent may merge its own green PR only when one merge grant names every file the PR changes. `lanes.py check --merged --merge <files>` is the check, and the new model concept `grants` holds both. `board-claim` 0.5.0 says how to land work that has no issue of its own (claim the experiment's issue or the repo's standing chore item, a new template line), never to hand-write a field a profile sync `owns`, and when a grant allows a merge; the agent guard's refusal says the same. `board-report` 0.5.0 adds the sync-owned rule, `board-decompose` 0.3.0 parents items a sync creates once they exist, `board-review` 0.2.0 says how a lane finds `agent-review` requests, and BOARD.md rule 3 names sync-owned fields.

## 2026-11-03

* **Added**: evidence on the issue and review requests (kit 0.21.0). The new model concept `evidence-places` says where each kind of evidence goes: the PR's evidence table stays the gate, and GitHub issue artifacts keep the approved plan, outside links and reports on the issue; a sub-issue is never evidence. The server spec gains the optional Issue artifacts group (`issue_artifact_list`, `_get`, `_create`, `_update`; no delete) and conformance A1 to A4. A new base label `agent-review` is a person's request for an agent to review an issue: `issue_labels` and `capture` refuse it from an agent (P4), a dispatching server starts a review run from it, and the new skill `board-review` does the review and posts one comment of findings. `board-report` 0.4.0 and `board-decompose` 0.2.1 point at the evidence rule. Profiles must add `agent-review` when they repin.
* **Added**: epic shape and board fields (kit 0.20.0). `board-decompose` 0.2.0 writes the epic body with every section the decomposition research calls for (Problem, Outcome check, Scope, Out of scope, Stories, Decisions, Risks and open questions, Gates) and fills each new item's board fields. The bodies live in `skills/board-decompose/templates.md`, and `templates/issues/` ships them as GitHub issue templates. The new model concept `board-fields` says who writes each standard field (Epic, Size, Priority, Lane, Owns, Gates, Agent, Last report, Start date, Target date) and when, and how a card waiting on a person's gate says which gate and what is asked; profiles should give the owner's `needs:*` label its own column instead of `Blocked`. `board-report` 0.3.1 points at it.
* **Added**: view filters (kit 0.19.0). A profile must not declare a view whose filter uses a deprecated qualifier; the first is `last-updated:`, replaced by `updated:` with a date (`is:closed updated:>=@today-7d`). GitHub warns on it and will drop it. A live view that still has one is reported for a person with the filter to type, because the API cannot edit a view, even when the repo kept the view. Conformance gains P9, and `board-onboard` 0.5.0 checks the repo's live views.
* **Fixed**: the Codex SessionStart hook initialises `.gtd/kit` before it runs `agent_guard.py` (kit 0.18.2), as the Claude hook does. Before, a Codex-only session in a fresh checkout never ran the guard and the linked skills stayed unresolved.
